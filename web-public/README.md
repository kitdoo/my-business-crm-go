# PHOMI Srbija — публичный сайт

Отдельный Nuxt 3 проект (см. `docs/TZ_PHOMI_Public_Site_v1.md`), не зависящий
от `web/` (админ-панель) в рантайме — только читает тот же бэкенд.

## Быстрый старт

```bash
cd web-public
npm install
cp .env.example .env   # заполнить значения, см. ниже
npm run dev
```

## Backend setup

Каталог читает бэкенд **полностью анонимно** — `guest` в `internal/rbac`
это отдельная роль для людей с read-only доступом в саму админку, к
посетителям публичного сайта отношения не имеет, поэтому этот путь не
используется.

Вместо сервисного аккаунта три метода помечены исключением в gRPC
auth-интерсепторе (`internal/transports/grpc/interceptors/auth/auth.go`,
`atlasauth.WithIgnoreMethods`) — так же, как `Login` исключён, чтобы
получить токен в принципе можно было без токена:

- `ProductsService.List`
- `PricesService.Get`
- `CategoriesService.List`

Вызов без bearer-токена пропускает и RBAC-интерсептор (там нет
пользователя в контексте — проверять нечего), т.е. эти три метода отвечают
любому, кто может достучаться до gRPC-порта. Это безопасно ровно потому,
что gRPC-порт сегодня не выставлен в интернет — к нему обращаются только
два серверных BFF (`web/`, `web-public/`), браузер никогда не видит его
напрямую. Раз бэкенд сам не ограничивает, какой `filter` пришлёт анонимный
вызывающий, единственная защита от утечки Draft/Inactive товаров —
`server/utils/catalogClient.js` в этом проекте, который **всегда**
прописывает `statuses: [ACTIVE]` сам, независимо от того, что просит
браузер.

Никаких дополнительных шагов (создавать пользователя, трогать `.env`
бэкенда) не требуется — `web-public/.env` достаточно `NUXT_GRPC_BASE_URL`.

## Что реализовано (см. `docs/TZ_PHOMI_Public_Site_v1.md` §11 DoD)

- Главная страница, все секции из ТЗ §4.3 (заглушки для текста/картинок —
  см. ниже).
- `/katalog` и `/katalog/[sku]` — читают реальные данные бэкенда
  (анонимно, см. "Backend setup" выше).
- `/postani-diler` (+ `/postani-diler/hvala`), `/kontakt`, `/projekti`,
  `/o-nama` — отдельные страницы (вариант A из ТЗ §4.1a).
- Формы "Стать дилером" / "Контакт" — с Zod-валидацией, honeypot-полем и
  rate-limit на сервере; отправка идёт через бэкенд
  (`server/utils/notificationClient.js` → `NotificationsService.Send` по
  gRPC, авторизация статичным ключом клиента — `NUXT_GRPC_CLIENT_KEY`,
  см. `internal/transports/grpc/interceptors/clientkey`), бэкенд шлёт
  письмо на `crm.smtp.to`.
- i18n `sr/en/ru`, `sr` без префикса в URL, `en`/`ru` с префиксом,
  `hreflang` через `useLocaleHead()`.
- `robots.txt`, `sitemap.xml` (включает реальные товары каталога).
- Иконка входа в админку в TopBar и футере — ссылка на
  `NUXT_PUBLIC_ADMIN_URL` (по умолчанию `/login` в `web/`), открывается в
  новой вкладке.

## Заглушки, которые нужно заменить

- **Картинки** — все под `public/images/` (в т.ч. `public/images/projects/`)
  сейчас SVG-заглушки с подписью "REPLACE: ...". Заменить файлами с теми же
  именами и расширением `.svg`/`.jpg` (если меняете расширение — поправить
  ссылку в соответствующем компоненте/`config/projects.js`).
- **Тексты** — секции главной, "О нас" и т.п. отмечены `[Zamenite ovaj
  tekst...]` в `i18n/locales/*.json` — это плейсхолдеры, не финальный
  копирайт.
- **Логотип** — `public/images/logo-phomi.svg`, простая текстовая заглушка.
- **Решение по ТЗ §4.1a** уже зафиксировано (отдельные страницы), §7.1
  (форма → заглушка) тоже — при необходимости поменять см. выше.
